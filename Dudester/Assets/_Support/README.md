# Dudester

Готовая сцена: `Assets/_Presentation/Scenes/Main.unity`.
Редактор: **Unity 6000.3.8f1**. Графика: **Built-in Render Pipeline**.

## Запуск

1. Открыть этот проект в Unity 6000.3.8f1 и дождаться импорта.
2. Открыть `Assets/_Presentation/Scenes/Main.unity`.
3. Нажать Play в Unity, затем **PLAY** в меню игры.
4. Двигаться WASD, стрелками или экранным джойстиком. Стрельба автоматическая.
5. После поражения кнопка **RESTART** полностью сбрасывает сессию.

Сцена уже сохранена со всеми ссылками и первой включена в Build Settings.
Генератор запускать для обычной игры не требуется. Для ввода с клавиатуры окно Game должно иметь фокус.
Левый стик геймпада также поддерживается. Джойстик работает с касанием или перетаскиванием мышью.

## Игровые системы

- Арена 22 × 22, ортографическая камера с автоматической подстройкой под соотношение сторон.
- Отзывчивое перемещение без ускорения по диагонали, ограниченное ареной.
- Автоматический захват ближайшей доступной цели; сохранение захвата до смерти или выхода из радиуса.
- Видимые снаряды с проверкой всего отрезка движения за кадр, без дорогой физики.
- Бесконечные melee-враги: преследование, небольшое взаимное расталкивание, контактный урон с перезарядкой.
- Здоровье, время выживания, убийства, главное меню, HUD, Game Over и Restart.
- Вспышка дула, отдача, след снаряда, красные частицы попадания, вспышка через MaterialPropertyBlock,
  уменьшение врага при смерти, эффект появления, отклик игрока и небольшая встряска камеры.
- Шесть оригинальных коротких WAV: выстрел, попадание, смерть врага, урон игроку, UI, смерть игрока.
- Нет опыта, уровней, магазина, инвентаря, волн или условия победы.

## Архитектура

Весь C# находится в `_Source`. Пространства имён совпадают с названиями систем, без общего префикса.

| Система | Ответственность |
| --- | --- |
| `CoreSystem` | `GameSession`: состояние и порядок обновления; `ArenaCamera`: кадрирование и встряска |
| `InputSystem` | Чтение установленного Unity Input System; независимый `VirtualJoystick` |
| `PlayerSystem` | Перемещение, HP, неуязвимость на 0.3 секунды после урона, события |
| `EnemySystem` | Поведение врагов, спавн, список активных целей, разделение соседей |
| `CombatSystem` | Автооружие, полёт/попадания, вспышки, сервис VFX |
| `PoolSystem` | Предварительно заполненный ограниченный пул компонентов |
| `UiSystem` | Представление состояния, кнопки и Safe Area; боевой логики нет |
| `AudioSystem` | Громкость, 12 аудиоканалов, ограничение частоты одинаковых звуков |

`GameSession` связывает системы сериализованными ссылками. C# events передают урон, смерть, выстрел,
изменение статистики и состояния UI. Подписки симметрично снимаются в `OnDisable`.
На Restart сцена не перезагружается: объекты возвращаются в пулы, состояния систем сбрасываются.
Номер поколения врага не позволяет сохранить ошибочный захват на повторно выданный объект пула.

Runtime assembly: `Dudester.Runtime`. Генератор изолирован в Editor assembly.
Play Mode-тесты находятся в отдельной test assembly и не входят в обычную сборку.

## Настройка через Inspector

- **Player / PlayerController:** Max Health, Movement Speed.
- **Player / Weapon / AutoWeapon:** Attack Range, Damage, Fire Interval, Projectile Speed, Projectile Lifetime.
- **Enemy.prefab / EnemyController:** Health, Movement Speed, Contact Damage, Attack Cooldown, Attack Range.
- **EnemySpawner:** Max Active Enemies, Initial Interval, Minimum Interval, Ramp Duration.
- **AudioService:** Master Volume, Clips, Voices.
- **Projectile Pool:** Capacity и Projectile Radius.

Начальные значения: 100 HP, скорость игрока 5.4, HP врага 3, скорость врага 2.05,
контактный урон 12, радиус оружия 8, интервал выстрела 0.24 секунды.
Интервал спавна линейно снижается с 1.25 до 0.27 секунды за 150 секунд, далее остаётся постоянным.

## Производительность

Заранее создаются максимум 48 врагов, 64 пули и по 18 объектов для трёх типов VFX.
При исчерпании пула новый объект не создаётся. Статичная арена объединена в пять мешей по материалам.
Материалы общие; при уроне используется MaterialPropertyBlock, без `renderer.material`.
В боевом Update нет LINQ, поиска объектов сцены, Instantiate/Destroy или создаваемых коллекций.
HUD форматирует время один раз в секунду. Подписки не создаются заново при Restart.
Настоящие тени и постобработка выключены; контактные тени — простые плоские меши.
Физика и NavMesh для движения и снарядов не используются.

## Генератор

Меню **Dudester → Generate prototype assets and Main scene** пересоздаёт только ассеты прототипа
по фиксированным путям и сохраняет их GUID. Объекты и записи Build Settings не дублируются.
Это также сбрасывает ручные изменения сгенерированной Main-сцены и её ресурсов к исходной конфигурации.
В интерактивном редакторе сначала предлагается сохранить текущую изменённую сцену.
Проверка **Dudester → Validate saved scene** ищет отсутствующие скрипты и незаданные ссылки в наших компонентах.

Исходный проект использовал URP. Для Built-in сняты ссылки Render Pipeline в Graphics Settings
и обоих Quality Levels. Исходные URP-ресурсы и установленные пакеты сохранены, версия Unity не менялась.
Старую SampleScene, содержащую исходные URP-настройки, следует рассматривать как сохранённый исходник.

## Проверка

В Unity: **Window → General → Test Runner → PlayMode → Run All**.
Тесты загружают сохранённую Main-сцену и запускают реальный игровой цикл.
Итоговые результаты и ограничения проверки описаны в `QA/Verification.md`.

## Границы текущего среза

- Баланс — стартовая настройка вертикального среза, без длительного пользовательского плейтеста.
- Сенсорный ввод реализован; реальные мобильные браузеры нужно проверить после экспорта.
- DOTween и Unity Playworks не устанавливались; экспорт, публикация и проверка их совместимости не выполнялись.
- Звуки синтезированы генератором, музыка не добавлена. У всех звуков есть регулировка общей громкости.
- Профилирование на целевых рекламных сетях и слабых мобильных устройствах ещё предстоит.
- UI на английском; поддерживаются landscape и portrait, безопасная область учитывается.
